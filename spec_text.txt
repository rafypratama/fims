3. Customer, Brand & Produk — Sistem Mapping
Ini adalah fitur paling kritis dalam FIMS. Setiap customer memiliki nama brand utama dan katalog produk eksklusif dengan harga khusus. Saat membuat invoice atau surat jalan, pengguna cukup mengetik nama customer atau nama brand — sistem langsung menyaring dan menampilkan hanya produk milik customer tersebut.
3.1 Konsep Hierarki Data
3.2 Cara Kerja Smart Autofill
Alur pengisian saat membuat Invoice atau Surat Jalan:
Pengguna mulai mengetik nama customer atau nama brand di kolom pencarian.
Dropdown real-time muncul menampilkan customer/brand yang cocok beserta preview jumlah produk.
Setelah dipilih, sistem HANYA menampilkan produk milik customer/brand tersebut — produk lain tidak muncul.
Produk default milik customer tersebut terisi otomatis: nama produk, harga, satuan, dan spesifikasi.
Pengguna dapat mengubah qty, harga (override manual), atau menambah/hapus item sesuai kebutuhan transaksi.
3.3 Penambahan Brand / Customer Baru
Saat Admin menambahkan customer atau brand baru ke Master Data:
Input wajib: Nama Customer/Perusahaan, Nama Brand Utama, PIC, Kontak, Alamat.
Setelah customer dibuat, Admin langsung menambahkan katalog produk khusus customer tersebut.
Setiap produk dalam katalog memiliki: Nama Produk, Kode Produk (opsional), Satuan, Harga Default.
Harga dapat di-override per transaksi tanpa mengubah harga default di master data.
Satu customer bisa memiliki lebih dari satu brand; pencarian bisa dilakukan via nama customer ATAU nama brand.
3.4 Isolasi Data Antar Customer
Produk customer A tidak pernah muncul di form customer B — isolasi penuh.
Jika ada nama produk yang sama di dua customer berbeda, sistem membedakannya berdasarkan customer_id.
Pencarian global (header) tetap bisa mencari lintas customer, tetapi form invoice/surat jalan tetap terisolasi.

6. Master Data & Import Excel
6.1 Modul Master Data
Customer: nama, brand utama, PIC, telepon, email, alamat, status aktif/nonaktif.
Produk per customer: nama, kode, satuan, harga default — terisolasi per customer.
Rekening bank: nama bank, nomor rekening, nama penerima (tampil di PDF invoice).
6.2 Import Excel — Harga per Customer
Tersedia 9 file Excel yang harus diimpor: Harga Chumairah.xlsx, Harga Jealous.xlsx, Harga Jitu.xlsx, Harga Laskin.xlsx, Harga Madira.xlsx, Harga ML.xlsx, Harga Orchidea.xlsx, Harga Shieeby.xlsx, Harga Talkme.xlsx.
Batch upload semua file sekaligus di halaman Data Onboarding.
Nama customer dibaca otomatis dari nama file ("Harga [NamaCustomer].xlsx").
Sistem memetakan produk + harga ke customer yang sesuai, mengisi mapping otomatis.
Preview data sebelum import, validasi format, mode upsert (update jika ada, tambah jika baru).
Laporan hasil: jumlah berhasil, gagal, dan duplikat yang di-skip atau di-update.
6.3 Migrasi Riwayat Invoice (PDF Lama)
Tersedia file PDF lama per transaksi (Invoice 01 ML.pdf, Invoice 02 Madira.pdf, dst.). Dua jalur impor:
Jalur 1 — Parsing otomatis: sistem membaca teks PDF, mengekstrak data invoice ke form verifikasi sebelum disimpan.
Jalur 2 — Input manual dipandu form: PDF tampil di panel kiri, form input terstruktur di panel kanan untuk entri cepat jika PDF tidak bisa di-parse.
Setelah diimpor, riwayat invoice dapat dicari, difilter, dan dijadikan referensi.
6.4 File Referensi Customer
File Bonus Cust Faacos.pdf dapat diupload sebagai lampiran di master data customer.
Konten bisa dijadikan acuan pengisian data customer secara manual.

10.3 Stack Teknologi yang Direkomendasikan

11. Alur Data Onboarding (Setup Awal)
Halaman khusus yang hanya diakses Admin, tersedia saat setup awal maupun kapan saja. Memandu Admin mengimpor semua data existing tanpa input manual satu per satu.
Langkah Onboarding
Upload semua file Excel harga (batch) → preview per file → validasi → import → konfirmasi mapping customer-produk.
Upload file PDF invoice lama (batch) → pilih mode parsing otomatis atau manual → review per dokumen → simpan ke database.
Upload file referensi customer (Bonus Cust Faacos.pdf) → lampirkan ke master data customer.
Laporan akhir onboarding: jumlah data berhasil diimpor, gagal, dan duplikat yang di-skip atau di-update.
Semua proses import berjalan secara async (background) dengan progress indicator. Jika parsing otomatis gagal pada sebagian field, sistem menandai field tersebut dan meminta konfirmasi manual — tidak menolak seluruh dokumen.
12. Prinsip Arsitektur
Scalable & modular: setiap modul (invoice, surat jalan, customer, produk) berdiri sendiri dan mudah dikembangkan.
Keamanan: autentikasi JWT, role-based access control, log aktivitas seluruh aksi Admin dan Karyawan.
Cross-platform: satu codebase frontend untuk web, desktop, dan mobile.
Offline-capable (nice to have): mode offline untuk mobile dengan sinkronisasi saat online.
API-first: semua fitur exposed via REST API, memungkinkan integrasi masa depan.
Sistem siap digunakan sebagai platform operasional jangka panjang, bukan sekadar MVP.
